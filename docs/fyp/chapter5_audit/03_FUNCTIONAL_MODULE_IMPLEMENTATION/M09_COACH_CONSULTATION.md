# M09 — Coach scheduling and consultation

**Status:** Implemented but Not Fully Verified. Manual and historical controlled UAT is time/environment-bound. Source records consultations and status; auditioned independent payouts/teleconsultation quality was not recovered.

**Interface and data:** Coach Home / Roster / Session Details route to current schedule and bounded completed history. Consultation Notes presents authorized notes or publish affordance. Client posture information is obtained by a scoped callable independent of booking display. Pair-chat threads support the shared Member/Coach relationship; M07 documents booking formation. Screens include `apps/mobile/lib/features/coaching/presentation/coach/roster_screen.dart`, `coach_session_details_screen.dart`, `consultation_notes_screen.dart`, `client_posture_screen.dart`, and `message_inbox_screen.dart`. Related adapters are `apps/mobile/lib/infrastructure/firebase/firebase_module9_repository.dart`, `firebase_booking_communication_repository.dart` and `firebase_coach_booking_cancellation_repository.dart`.

**Finishing a consultation:** `bookingConsultationNotes` verifies email, current scoped participant and active organization. Only the assigned Coach with current active branch access may publish. Notes are trimmed and limited to 1–5,000 characters. A confirmed booking must have ended, and the server accepts only one published note. Transactionally, it writes `orgs/{org}/bookings/{id}/consultation/current` with Member/Coach ownership and publication timestamp, marks parent `completed`, and writes a receipt bound to actor, booking and text fingerprint. Same request replay returns existing content if contract matches. A separate Member role may read only its own notes. Consult completion and analytics therefore depend on persisted status rather than tapping the UI alone. See `functions/src/modules/coaching/booking-consultation-service.ts:10–73` and [S-M09-01](../evidence/code_snippets/S-M09-01.md). Coach cancellation is separate under `coach-booking-cancellation-service.ts`, with payment review consequences. `client-posture-service.ts` and `coach-performance-service.ts` implement scoped reads.

**Evidence:** `functions/test/booking-consultation.test.ts`, `booking-communication.test.ts`, `coach-booking-cancellation.test.ts`; `apps/mobile/test/consultation_notes_screen_test.dart`, `booking_communication_ui_test.dart`, `coach_roster_summary_render_test.dart`. `docs/integration/coaching-completion-uat.md` records historical completion scope. Capture an ended synthetic booking from assigned Coach, an allowed note (synthetic wording) and the Member's readback card. Core consultation management can be reported independently of external Google delivery and financial reconciliation.

**Chapter 3 trace.** FR-9.1–9.6 (`c3.md:7395–7410`). Upcoming/past bookings, client posture, messaging, cancellation, notes and Coach performance map to the historical requirements. Current notes drive booking completion through a checked transaction.
