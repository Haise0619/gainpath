## Interface and workflow

Rewards & Check-in provides the daily action, current balance, history, shop, reward detail and My Rewards. Home also surfaces check-in. Fitness Arcade has game details, Fun or Earn entry, live motion play, results, personal best and leaderboard surfaces. Member Achievements shows earned/locked training and check-in badges, with an Android share path. The locked Free previews intentionally still show content. Read/loading, policy denial and recoverable error are separate UI states. Relevant clients are under `apps/mobile/lib/features/gamification/presentation/member/`, especially `rewards_check_in_page.dart`, `verified_reward_shop_view.dart`, `member_achievements_screen.dart`, `mini_game_details_screen.dart` and `locked_rewards_preview.dart`. `AppCheckInCubit` and `RewardsFeatureHost` connect views to session-scoped Firebase repositories. Changing a displayed balance does not create a server award.

| Operation | Current policy and persistence | Implementation evidence |
|---|---|---|
| Digital check-in | Base 50 points, one claim per Malaysia calendar day. Day identifier is based on UTC+8. Adjacent valid dates extend the streak and a gap restarts it. A transactional receipt, profile/streak and wallet protect against multiple claims. Check-in badges at streaks 1, 3 and 7. | `functions/src/modules/gamification/app-check-in-service.ts:9–17,38–end` |
| Premium check-in supplement | Separate enabled/time-bounded server policy with validated positive amount, headroom and current Premium eligibility. Missing or invalid configuration leaves base earning. | `functions/src/modules/gamification/premium-check-in-policy.ts:6–18` |
| Counted AI exercise | 10 points once per distinct exercise per Malaysia day. Eligibility checks a completed current published routine, zero manual sets, matching published set/rep prescription, validated owned backup and a linked realCamera session within the attempt/current day. A routine attempt may yield several individually accepted exercises. Same-attempt replay returns no new points. | `functions/src/modules/gamification/ai-workout-points.ts:10–127`, commit `f81fb2d` |
| Guided video | Five points for an eligible completed exercise-set sequence; expected set count and per-set duration derive from the current published entry. Transaction checks timer/run identity and elapsed server time, with 30-minute idle window. The final award shares the Member, exercise and Malaysia-day key used by AI earning. Set callbacks and run replays do not create a second award. It establishes elapsed time/completion inputs, without proving real movement. | `functions/src/modules/gamification/video-workout-points.ts:10–118`, commit `ec24d7a` |
| Workout points ledger | AI and video both add to one Malaysia-day `rewardAwards/workout_day_…` entry while maintaining source receipts and `rewardBalances/{member}`. Qualifying exercise completion and backup quality are different from medical or physical validation. | `ai-workout-points.ts:108–127`, `video-workout-points.ts:99–118` in the directory above |
| Arcade participation | Reach & Tap uses 20 once per eligible Malaysia day, shared configurable cap clamped to 60 for that route. Finish data must match the same scoped round, have 40,000 active ms and valid sequence/expiry. Participation and competition are distinct from the disabled verified-motion reward policy. | `functions/src/modules/gamification/mini-game-participation.ts:13–14,76–115`, `mini-game-reward-policy.ts:6–9` |
| Earned points leaderboard | Read model built from eligible earnings. It is a distinct quantity from the spendable balance after redemptions. | `functions/src/modules/gamification/earned-points-leaderboard.ts` |
| Shop / vouchers | Server reads effective tier, item/policy and wallet. A member-scoped request identifier binds replay to the same item. A transaction creates an issued redemption, reserves stock and decrements wallet. Current detail may project expiry from the issue, and an expired voucher cannot be fulfilled. Points remain spent. Admin fulfilment checks authority and records actor/timestamp. | `functions/src/modules/gamification/verified-rewards-service.ts:95–156,199–223` |
| Training achievements | Server walks paged check-in/workout sources, validates saved envelopes, checks declared completion and totals, and returns typed catalogue/progress, with date/lifecycle logic and eligibility bounds. | `functions/src/modules/gamification/member-achievements.ts:16–33,37–161,162–end`; `docs/integration/member-achievements-system.md` |
