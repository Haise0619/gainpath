# M08 — Coach account and profile

**Status:** Implemented but Not Fully Verified. Historical rollout evidence is not a new lifecycle exercise. The same Flutter mobile app contains the Coach role shell. Admin provisions a Coach and sets directory status. Coach account/settings reads verified own identity and current organization/branch facts, then supports professional data, photo and certification submissions. Member sees a published directory projection. Relevant sources are `apps/mobile/lib/app/shells/coach_shell.dart`, `apps/mobile/lib/features/identity/presentation/coach/`, `apps/admin_web/lib/features/identity/`, and `functions/src/modules/coaching/coach-management-callables.ts`.

**Persistence and validation:** `coach-profile-service.ts:11–12,30–56` allowlists display name, specialty, bio, tags, years of experience, consultation fee in minor units and photo path. Separate private work data and `orgs/{org}/coaches/{uid}` public projection prevent certification evidence from going to the directory. Saved profile commands require the active Coach; publication/update runs against authorized current org/branch scope, signed-in identity and revision. Revision mismatch and request fingerprint reuse prevent accidental overwrites; approved certification counts/verification are maintained in the public projection without displaying certification documents. `functions/src/modules/coaching/coach-profile-service.ts:57–95,96–end`. Certification submit, archive, Admin review and read are separate actions with checked upload and visibility scope. See `functions/src/modules/coaching/coach-certification-service.ts:10–end`, `coach-photo-service.ts`, `coach-account-service.ts`.

**Workflow:** Admin provisions a Coach through identity management → eligible Coach signs in and fills account/professional fields → optionally uploads a photo/certification → assigned Admin reviews certification/directory details → enabled, published Coach projection becomes visible to authorized Members and eligible booking/recommendation services. A private unsubmitted draft and a published active profile are separate states. Scoped profiles and fee facts flow to M07 and M13. Missing image/document and stale revisions have error/retry surfaces; a review action does not confer a clinical qualification.
