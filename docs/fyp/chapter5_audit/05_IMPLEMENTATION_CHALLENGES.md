# 5.1.5 Implementation challenges and refinements

| Problem and technical cause | Implementation response | Evidence and remaining question |
|---|---|---|
| Camera preprocessing and inference incurred different queue/worker/render delays. | Preserve bounded work, later move hot preprocessing and optional GPU execution into dedicated/adapted paths, retain CPU fallback. | October historical paired comparisons in `docs/architecture/2026-10-03-pose-step2c-physical-comparison.md:78–120` and later GPU experiments. Worker/callback-to-paint and external observed gesture latency are different metrics. |
| Stale frames and steady inference delay sometimes reset exercise calibration or cleared preview. | Separate incoming capture age, accepted delivery absence and display hold. A held display overlay is never fed into the analyzer. | `docs/STATUS.md` November 6 changes; pose pipeline/evaluation and regression tests. Validate through occlusion, orientation and camera interruption. |
| Floor push-up perspective, side and ambiguity influence projected limb geometry and phase admission. | Independent left/right setup, confidence and geometry checks, bounded recovery, conservative unscored fallback and completed-cycle gating. | `docs/integration/standard-floor-push-up.md` and physical acceptance protocol. Right-hand evidence exists; matched left, device and score acceptance incomplete. |
| Speech scheduled from transient frame conditions could repeat or arrive too late. | Move feedback onto identified events, prune on stale/lifecycle changes, prioritize cues, apply cooldown and native absolute start deadline. | [Voice implementation](04_CORE_TECHNOLOGY_IMPLEMENTATION/VOICE_FEEDBACK.md) and November native audio evidence. True onset under noise/thermal stress pending. |
| A matching status alone could over-credit payment, double-allocate a booking or duplicate a reward. | Hold and transaction invariants, independent provider readback, command fingerprints, accounting buckets and durable replay-safe receipts. | M03, M04 and M07. Sandbox acceptance historically exists. Broad concurrent tests are governed by current run results. |
| Android interruption can separate local completion from cloud backup. | Scoped journal/checkpoints, retryable backup scheduler, record-key/digest comparison and explicit conflict handling. | `workout-backup.ts:43–76`, member continuity tests and `docs/integration/workout-backup-default-availability-2026-11-15.md`. |
| Heterogeneous measurements and synthetic cohort activity could yield misleading merged analytics. | Preserve provenance, version-compatible form buckets, partial/unavailable states and separate settlement evidence from scenario presentation. | M05/M12/M13, `docs/integration/admin-reports-analytics-final.md:23–37,57–117`. |
| Admin reported multiple overview requests and redundant off-tab loading. | Defer Fitness/Engagement loads and deduplicate same-query in-flight requests, keeping refresh and visible state. | Historical widget counters compared mounted requests, not production milliseconds. Record time and Firestore Reads independently for real service performance. |
| Branches progressed independently. | Preserve exact working-tree and commit attribution for recent OTP, announcements, rewards and Admin calendar work. | `4ed106b`, `65324d1`, `d0a0866`, `9c0ee5c`, `f81fb2d` and local file hashes. Contract consistency is an explicit limitation. |
| Architecture gate found production feature coupling while checking the current tree. | Record the actual two imports and retain the gate result. | `evidence/test_logs/architecture.txt`. Do not equate a successful unit run with a clean workspace gate. |
