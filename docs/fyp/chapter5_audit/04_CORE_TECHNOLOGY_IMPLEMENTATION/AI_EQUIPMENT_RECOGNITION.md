# 5.1.4.7 — AI equipment recognition

The equipment scanner uses Gemini cloud image recognition followed by deterministic client-side catalogue matching. No trained weights or training set specific to the app were found for this feature. The scanner and the local pose tracker have different image data flows.

1. `EquipmentScannerScreen` captures a still with the camera or uses `LocalEquipmentImagePicker`. Gallery picks accept JPG/PNG/WebP, verify magic bytes and cap source file size at 5 MiB and cap decoded dimensions. The picker rejects above 24 MP, targets max dimension 1024 px with proportional sizing, and encodes resized/WebP/above-1-MiB inputs to PNG. These picker safeguards should be attributed to that path. Camera uses its own capture path. `apps/mobile/lib/infrastructure/local/equipment_image_picker.dart:15–109`, `apps/mobile/lib/features/workout/presentation/member/equipment_scanner_screen.dart:210–333`.
2. Call `identifyEquipmentCommand` with scoped organization, image MIME and encoded bytes. Function enforces App Check, signed-in email-verified active Member and org lookup. It checks base64 length ≤6 MiB (up to 4.5 MiB decoded) and JPEG/PNG signature concordance. Secret Manager key stays on server. Cloud model `gemini-3.5-flash-lite` receives prompt and image in `inlineData`, with JSON response MIME and temperature 0.1. Provider HTTP budget is 20 seconds; callable timeout is 30 seconds. Provider failures return an unavailable state. `functions/src/modules/workouts/equipment-scanner-callable.ts:23–142,148–171`.
3. Parse first candidate text as JSON. A result includes name ≤160 characters, at most 20 aliases each ≤160 characters, optional category, finite confidence [0,1], and Boolean gym equipment flag. An uncertain result <0.80, non-gym scene, blank label or missing eligible catalogue cannot open a target. Confidence is a model judgment without calibration data.
4. For active inventory, normalize names/aliases to lowercase ASCII alphanumeric tokens and compute the maximum model name/alias match score for each item. Exact label gives 1.0; normalized substring gives \(0.85+0.10\min(|q|/|n|,|n|/|q|)\); exact standard synonym scores .95, contained synonym .88; token Jaccard \(J\ge .5\) gives \(.70+.15J\); optional category-in-text gives .65. Top score <.60 rejects. Multiple candidates with scores ≥.65 and within .15 of top enter disambiguation. Single match or chosen candidate still requires confirmation. Example for a synthetic catalogue containing only Squat Rack: “Power Rack”, confidence .85, maps to known .95 alias and requests confirmation. See [S-EQP-01](../evidence/code_snippets/S-EQP-01.md).
5. The scanner reads active equipment under the session organization and iterates catalogue pages instead of restricting inference to the first screen. Chosen item opens the existing equipment details and associated exercise/tutorial routes; Gemini does not generate those records or prescribe a plan. Empty catalogue, offline, denied camera, ambiguous/no-match and retry/browse have distinct presentations. `apps/mobile/lib/infrastructure/firebase/firebase_equipment_reader.dart:25–end`; scanner `230–285,600–end`; `apps/mobile/lib/features/workout/presentation/shared/equipment_detail_screen.dart`.

The image is sent off-device through the callable to Gemini; application code does not persist it as a cloud dataset. Provider processing/retention requires separate evidence. The UI and service do not return raw model text, and the user should frame just equipment for evaluation. The historical activation readback confirmed the configured callable and a text-only provider diagnostic. Physical-photo recognition still needs evaluation.
