# Pose core technology assessment

Date: 2026-10-12. Scope: an audit of the current working tree and retained evidence, plus a proposed validation plan. This document does not authorize tuning, installation, device operation, deployment, or server enablement.

## Assessment

GainPath has a real Android camera → custom BlazePose TFLite → landmark overlay pipeline, a provisional side-view squat analyzer, offline audio arbitration, durable account-scoped local results/history, and optional consent/outbox/callable integration. These software boundaries are implemented. **Anatomical accuracy, real-human squat/correction accuracy, satisfactory dynamic response, sustained device performance, and end-to-end real acceptance are not quantitatively established.** The backend's empty enabled-tuple policy deliberately preserves that distinction.

The retained Xiaomi experiments demonstrate computation improvements and some improved overlay continuity. They also show moving-arm discrepancy before filtering, additional refined-to-filtered lag, confidence-dependent missing links, and freshness clears of otherwise valid predictions. Neither confidence nor the estimated form score is a ground-truth accuracy percentage. The model's published benchmark results cannot be substituted for this application's measurements.

The thesis reference `C:/Users/Ngzhe/Documents/A-FYP/Final Md file/c2.md` and its aligned `GainPath_Chapter_4_9_Aligned_Algorithm_Design.md` describe intended technology and eight algorithms. They are design references, not execution instructions or evidence of implemented behavior. In particular, the current adapter copies camera planes and uses custom TFLite preprocessing/inference; it does not implement the reference's ML Kit native/zero-copy processing or demonstrate 30 pose updates/s within 33 ms. Its squat geometry is 2D, despite retaining model-estimated world coordinates.

The [real-workout handoff](../architecture/2026-10-02-real-squat-contract.md), [initial squat contract](../architecture/2026-10-02-real-squat-contract.md), [Step 3](../architecture/2026-10-08-step3-squat-processing.md), [Step 4](../architecture/2026-10-12-step4-real-workout.md), [Step 5 mobile](../architecture/2026-10-12-step5-mobile-sync.md), [Step 5 backend](../architecture/2026-10-12-step5-mobile-sync.md), and [Step 6](../architecture/2026-10-12-step6-development-deployment.md) distinguish software completion from physical acceptance. Statements such as “no Step 3/scoring/upload” in October 2–6 reports describe those historical experiments. They do not describe the October 12 working tree or impose a current prohibition on documenting subsequent work.

### CPU default and experimental GPU

Default CPU uses `tflite_flutter` 0.12.1, two interpreter threads and a persistent background Dart isolate containing both interpreters. Flutter's UI does not perform native inference. Background isolation reduces UI blocking, but camera copies still occur before dispatch and do not become zero-copy input.

The experimental [Dart GPU transport](../../apps/mobile/lib/infrastructure/pose/blazepose_gpu.dart) is guarded by `!kReleaseMode` and `GAINPATH_POSE_GPU`; comparison additionally needs `GAINPATH_POSE_GPU_COMPARE`. [Kotlin activity registration](../../apps/mobile/android/app/src/main/kotlin/com/zyang/gainpath/MainActivity.kt) registers the Java plugin. [GpuSessionOwner](../../apps/mobile/android/app/src/main/java/com/zyang/gainpath/GpuSessionOwner.java) owns construction/invocation/destruction on one OS thread; serialized Dart messages alone would not establish that affinity. [Native plugin](../../apps/mobile/android/app/src/main/java/com/zyang/gainpath/BlazePoseGpuPlugin.java) explicitly forces OpenCL, disallows precision loss, retains two residual CPU threads and disables XNNPACK. Failure is surfaced rather than relabeled GPU after CPU/OpenGL fallback. The cached Java artifacts are LiteRT/LiteRT-GPU 1.4.0; the historical extracted native build string `2.20.0-dev0+selfbuilt` is a different identifier.

Input float32 bytes travel through MethodChannel. Consumed outputs 0/1/3/4 return as byte buffers and are copied into aligned Dart float32 views. The heatmap alone is 64×64×39×4 = **638,976 bytes per landmark invocation**; transfer/copy/queue costs are material even when native GPU invocation is fast. Native invocation, adapter copy, round trip and transport remainder have separate timers. GPU does not eliminate Dart preprocessing or heatmap/inverse decode.

Busy operations are rejected, frames do not form a native backlog, and close alone queues after accepted work. Close is idempotent, attempts interpreter disposal before delegate disposal, and engine detach closes sessions. Parent initialization timeout/worker failure requests native cleanup; startup session ID exists before spawning. Current worker startup timeout is 30 s and close-response timeout 10 s, with active requests drained first. Normal route cleanup has device evidence; a universal bounded shutdown, cancellation-during-initialization stress result, or heap-leak proof does not follow from those timeouts.

GPU same-input agreement waits five seconds, attempts at most 24 frames, compares up to 12 landmark pairs, and closes CPU shadows. The same GPU-derived ROI/input is used for both landmark backends; independent detector/auxiliary ROI comparisons are scalar diagnostics. Shadow-active frames, including the completion frame, must be excluded from performance cohorts. Agreement checks are not a representative dataset or independent human anatomy labels.

| Callback→first CPU paint | Camera-copy/callback instrumentation and exact frame-bound painter record. Excludes later raster/compositor/display presentation. |
| Physical motion→display | One external synchronized view of actual motion and phone display. Score P→C, P→R/P→F directly; audio onset needs its own synchronized recording. |

For independent event brackets P=[p0,p1], C=[c0,c1], F=[f0,f1], report P→C=[c0−p1,c1−p0], C→F=[f0−c1,f1−c0], P→F=[f0−p1,f1−p0]. Compute the total directly rather than summing ranges and duplicating C uncertainty. Use real PTS, keep negative overlapping lower bounds, distinguish conservative visual enclosures from statistical confidence intervals, and censor absent/doubled/occluded events rather than interpolating a successful crossing.

## Proposed reproducible validation

### P1 — measurement and evaluator work

Create a reviewed private/consented dataset protocol before changing model/filter/rule thresholds. Preserve immutable original media, SHA-256, participant pseudonym, consent scope, device/OS/lens/driver, APK/code commit/dirty manifest, model/runtime hashes, rule version, flags, raw/upright dimensions, rotation, preview transform, declared view, clock origin, warm-up and thermal/power state. Use no raw pose/media in real activity submissions; private evaluation data must remain fixture provenance.

Proposed development pilot: 3–5 participants to settle annotation and the frozen protocol, within a total of 10–15 consenting adults, including 6–10 participant-disjoint held-out participants. Use at least two representative Android phones/performance classes and both visible anatomical sides. A third phone/class and a larger participant sample are optional robustness extensions; this proposal is not a power calculation or an achieved dataset. Aim for 10 full plus 5 partial attempts per person where feasible, with slow/normal/fast motions and supported lean cases under the frozen protocol. Report actual attempted, labelled, assessable, rejected and missing counts rather than hiding them from denominators. Add negative standing/sitting/turning sequences and startup bent/half cycle, interrupted ascent, repeated reversals, required-joint occlusion, person exit/re-entry/replacement, loose/tight clothing, low light, skin/body-proportion variation, off-frame feet, camera yaw/pitch/height/distance, rotation, mirrored bad input and uneven cadence. Never require unsafe movement to manufacture labels.

Independent annotators should label timestamp intervals for standing/calibration eligibility, descent, deepest posture, ascent, full completion, partial return, trunk-deviation onset/end and unassessable intervals. Annotate actual movement rather than commanded intent. In addition to those attempt/event labels, select 30–50 stratified exact input frames per person across phase, motion pace, supported deviations and occlusion; retain exact input timestamps/frame identity and document sampling and missing labels. Joint-centre labels need visible landmarks and documented occlusion uncertainty; 2D manual knee/trunk angles need common image axes and independently defined body segments. Two raters, blinded to predictions, label the frames/events, adjudicate disagreements and report their agreement. No independent 3D ground truth is available in the present evidence. A 3D claim would require a synchronized calibrated multi-view/motion-capture reference; a single displayed video or model-estimated world output cannot supply it.

Use participant-disjoint development/validation/test splits; hold out devices/sites where feasible. Freeze thresholds and event tolerance before opening the test split. Store an evaluation manifest rather than exporting personal paths/media into aggregate reports. Re-run the same frozen refined fixtures through both current and candidate logic; distinguish detector replay (same source images) from analyzer replay (same refined outputs) and live device performance.

Extend evaluation separately from real activity acceptance to expose per-attempt events, matched ground truth and abstention. Proposed matching: one-to-one full/partial completion events within a preregistered tolerance (initial candidate ±500 ms), minimizing timestamp difference without crossing attempt identity; unmatched prediction = FP, unmatched label = FN. Wrong full/partial class is a class error, not two mutually successful counts. Corrections match labelled deviation intervals plus a fixed allowed trigger delay; unmatched warnings are false corrections. Keep late/doubled/censored outputs explicit. Report sensitivity across ±250/500/1,000 ms rather than choosing the best tolerance afterwards.

| Metric | Required definition / denominator |
| --- | --- |
| Anatomical PCK | Upright unmirrored prediction versus independent joint centre, normalized by independently annotated near-side shoulder-to-hip torso length in the exact input frame; bilateral shoulder width is unstable in side view and is not this denominator. Report PCK at 0.05/0.10, pixel error and each essential joint. Define degenerate scale/occluded labels before scoring. Missing predictions count toward coverage/misses; never score only accepted joints without disclosure. |
| Angle error | Absolute knee/trunk error in degrees against independent same-view reference, MAE/median/p95/bias and pose/pace strata. Report label uncertainty and out-of-plane limitations. 3D MPJPE requires separate calibrated truth. |
| Static jitter | Held-only windows after settling; unique inference timestamps, reference-relative residual RMS and radial p95, drift and spectral/high-frequency variation. Separate raw/refined/filtered; do not reuse whole-phase R→F displacement as jitter. |
| FPS and dropouts | Camera callbacks, completed results, delivered nonempty, required-chain usable and unique painted FPS each use active-time denominator. Separate replacements, stale input/result, model absence, pose presence, joint rejection, clipping, expiry, lifecycle clears; report episodes/minute, unavailable fraction, recovery median/p95. |
| Timing | Queue, preprocess, native, decode/refinement, analyzer, filter CPU, UI and CPU paint each with samples/p50/p95/max. External P/C/R/F event ranges use actual PTS and interval censoring; report physical→overlay and analysis-trigger→audible onset separately. |
| Repetition | Full/partial event precision TP/(TP+FP), recall TP/(TP+FN), F1, count bias/MAE and completion delay, participant/session strata; report unfinished cycles separately. Equal aggregate counts are insufficient. |
| Form corrections | Per supported deviation event PRF, false cues per minute, missed episodes and trigger delay/duration. No unsupported valgus class or invented anatomical severity. Estimated score needs independent ranking/calibration evidence, not comparison to model confidence. |
| Abstention/confidence | Coverage of assessable frames/attempts, rejected fraction, false confident predictions and correctness versus confidence bins. Ground-truth unassessable intervals remain separately labelled. Report risk-versus-coverage rather than forcing a score from absent evidence. |
| Uncertainty | 95% intervals clustered/bootstrap-resampled by participant/session, not millions of correlated video frames; binomial intervals for event proportions where appropriate. Retain counts, missing labels, censoring and small strata. Conservative visual timing bounds are not confidence intervals. |

### P2 — physical validation without changing default rules

Replay the frozen current CPU/default configuration and gather genuinely captured side-view sessions on representative phones. Keep profile/release/build mode explicit, warm-up excluded but startup recorded, and use matched movement protocols plus counterbalanced run order for any backend candidate. Freeze everything except the preregistered tested variable. Use a stable external camera showing physical source motion and phone display together; score the actual joint clearly, without loose sleeve proxies where anatomical timing is claimed.

Run at least 20 minutes of continuously assessable full-body person input per phone; extend to 30 minutes if resources allow. Alternate ordinary movement, standing/holds and comfortable short repetition blocks with rest; this is an inference-endurance test, not a requirement for continuous squatting. Collect memory/thread/camera resource samples and temperature/thermal/power records before/during/after. Include repeated open/end, pause/background/manual pause, permission denial/retry, rotation including 180°, logout/account replacement, model initialization failure/cancellation and save/retry/restart history. Record dropped frames and censored events rather than silently selecting clean warmed interiors. Audible cue onset/interruption and offline voice availability require physical checks.

The following are **proposed initial acceptance targets for review; none is claimed achieved**. They must be agreed and justified with task-specific pilot variability before tuning or server enablement:

| Area | Proposed initial target |
| --- | --- |
| Essential joint anatomy | PCK@0.10 ≥95% on assessable side-view essential-joint labels, with coverage and participant-clustered 95% lower bound reported; no anatomical percentage is available today. |
| 2D angles | Knee MAE ≤5°, trunk MAE ≤5°, p95 absolute error ≤10° in the supported camera envelope; report rater uncertainty and yaw failures. |
| Reps | Full/partial event precision and recall ≥0.95 each; participant-clustered lower 95% bound ≥0.90; count MAE ≤0.5 per ten-attempt session. |
| Supported corrections | Trunk/depth precision ≥0.90, recall ≥0.90; false corrective cues ≤1 per five minutes of labelled acceptable movement; publish delay distribution and abstention. |
| Static stability | Required-joint reference-relative filtered RMS ≤1% of independently annotated near-side shoulder-to-hip torso length and radial p95 ≤2%, after settling; candidate must not degrade participant-level stability by >10%. |
| Continuity/coverage | ≥95% assessable required-chain coverage in supported unobstructed sequences; unplanned whole-overlay unavailable time <1%, no unexplained >500 ms blackout. Label occluded periods separately. |
| Performance | ≥15 usable pose results/s warmed on each supported device; callback→first CPU paint p95 ≤150 ms, separately physical motion→filtered display p95 ≤250 ms on identifiable uncensored events. The thesis ~30 FPS/33 ms remains an additional unachieved target if retained. |
| Audio | Analysis cue trigger→audible onset p95 ≤500 ms after preparation, with all lifecycle/priority cancellation checks; no <10 ms fast soundbank claim without the actual implementation and acoustic measurement. |
| Sustained resources | No crash/unbounded memory growth or surviving camera/owner after close; final steady performance within 20% of initial warmed cohort over at least 20 minutes per phone, extending to 30 minutes if feasible, with thermal context and failures retained. |

Meeting aggregate targets cannot excuse a materially poor participant/device/view stratum. Tune only on the development split, version every changed model/rule/filter policy and repeat the held-out evaluation. GPU adoption additionally requires representative identical-input tensor/refined/ROI/threshold-near agreement, real side-view quality, sustained resource evidence and release behavior; the existing tiny twelve-input differences are not that gate.

### P3 — reviewed tuple enablement and genuine history

Only after physical evidence review should a deliberate server policy change enable the exact organization/exercise/detector/model/scoring/view tuple. Validate one genuinely captured consented bounded submission, exactly one accepted server session across same/new-request retries, conflicting-payload rejection, revoked/rotated consent, account isolation, offline→restart→reconnect, durable receipt-before-accepted UI and retained local history. Keep fixture/demo sessions permanently outside real acceptance. Lead evaluation/gamification require separate approved features and tests; existing callables have no reward side effects.
