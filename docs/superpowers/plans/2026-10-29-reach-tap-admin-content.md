## Shared interface contract

- Keep `MiniGameContent.supportedId == 'move-catch-v1'` as compatibility default. Add `reachTapId == 'reach-tap-v1'` and `supportedIds` containing both. Add `defaults(String organizationId, {String gameId = supportedId})`; unsupported IDs fail. Add per-game identity label if useful. `validMediaUrl(url, org, kind, {String gameId = supportedId})` validates exact game-scoped paths. Serialization allows exactly the two implemented IDs, never arbitrary games.
- Backend `miniGameContentCommand` accepts optional `supportedGameIds` only on list. Absent means legacy Move & Catch-only response, preserving existing clients. Present must be a nonempty unique bounded subset of supported IDs; return exactly requested canonical order with explicit read-only built-in defaults for absent overrides. Save/upload exact per-game paths, receipts, fingerprints and cross-game idempotency guards; no content seeding/list writes or reward changes. Keep callable runtime/env/IAM/options unchanged; no Rules/index/storage policy changes needed for Admin-SDK content endpoint.
- Data reader sends both IDs. Explicit invalid-argument rejection of the list registry negotiation maps to `MiniGameContentRegistryUnsupported`; only that permits retry of the legacy list. Legacy response remains Move & Catch only; UI supplies explicitly labeled built-in Reach & Tap guide. `MiniGameContentRegistryStatus` optional capability interface exposes `bool get expandedRegistryAvailable` (remote reader/repository implement; false after explicit legacy fallback). Require exact requested IDs on successful negotiation; no duplicates, foreign org, unsupported or swapped game responses. Save response must match submitted gameId and fields, not just revision. Upload URL must match the selected game. Existing media/signature/size/session guards remain.
- Admin fills known implemented default rows when legacy server returns one, disables Reach & Tap edit when repository implements registry status and expandedRegistryAvailable=false, and shows an honest reload/unavailable hint. With new server both games can edit title/introduction/steps/cover/preview through same repository. No Add arbitrary game or editable engine/scoring fields. Reward policy remains Move & Catch-only with explicit separate Reach & Tap inactive status.
- Mobile loads both rows keyed by game/org; built-in fallback explicitly labeled on failed/legacy load. Reach & Tap card/details use authored title/instructions/media and route to ReachTapRoute(content:...). Extend existing details by game identity with proper Reach & Tap scoring/privacy/movement guidance, local Reach & Tap PB, never Move & Catch reward status/PB. Preserve explicit camera consent and existing game lifecycle/history/engine. Live ReachTap consent view can display scoped descriptive content but built-in consent/privacy/security rules cannot be removed by Admin prose.
