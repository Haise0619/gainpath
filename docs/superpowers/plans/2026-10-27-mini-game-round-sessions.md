# Mini-game round-session implementation plan

**Goal:** add protected, retry-safe server round timing and explicit pending-verification results while retaining disabled reward issuance.

**Architecture:** extend the existing Firebase/domain/data composition with a separate unexported round callable. One Member lease spans devices; server-generated attempt/challenge IDs bind ordered checkpoints and immutable completion receipts. The game reports timing only after a separate opt-in, never scores, frames or pose coordinates. Timing validation is not physical gameplay verification and cannot produce `miniGameVerifiedRounds` or award points.

**Tech stack:** Flutter/Dart ports and coordinator, Firebase Auth/App Check, TypeScript Firestore transactions, Vitest and focused widget/emulator tests.

**Rulings:** keep all camera/movement measurements on device, as promised by existing consent. Server timing checkpoints alone do not establish physical movement, so use `awaiting_verification`, never `verified` or `cameraEvidence:server_verified`. Issuance gates and accepted versions remain unchanged. Local preparation only; deployment, installation and optional new timing-data collection need separate release approval. Existing ordinary play stays available without network or opt-in. User requested direct implementation, so execute inline without intermediate design approvals or commits.
