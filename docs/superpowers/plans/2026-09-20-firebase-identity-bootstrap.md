# Firebase Identity Bootstrap Implementation Plan

> **Execution:** Implement inline with `superpowers:executing-plans` and use TDD for each behavior change.

**Goal:** Connect GainPath mobile and admin web to Firebase Authentication while server-side code assigns public registrants to the fixed `gainpath/main` member scope.

**Architecture:** An authenticated callable function owns self-registration provisioning and ignores client role or scope. FlutterFire gateways authenticate users, call the provisioner after member registration, read the authoritative membership documents, and adapt them to the existing SDK-free authentication repository. Firebase mode exposes only the identity slice until feature repositories receive real adapters; mock mode remains unchanged.

**Tech stack:** Firebase Functions v2, Firestore, TypeScript/Vitest, Flutter/Dart, FlutterFire Auth/Firestore/Functions/Core.

**Spec:** User-approved access model in this task and `docs/architecture/2026-09-19-architecture-implementation.md`.

## Global constraints

- Stable IDs are `gainpath` and `main`; display names remain editable document fields.
- Public registration can assign only role `member`, organization `gainpath`, and branch list `[main]`.
- Coach, staff, and administrator assignments remain server/admin-only.
- Firebase clients never write `/users` or `/orgs/*/members` directly.
- Unverified accounts cannot use protected Firestore data or callable business operations.
- Firebase mode must not silently expose in-memory feature data.
- Preserve mock mode and existing tests.

## Review focus

- A malicious public client cannot choose organization, branch, or elevated role.
- Repeated registration provisioning cannot overwrite editable organization/branch names or a conflicting membership.
- Missing, malformed, or inactive membership fails closed in Flutter and Functions.
- Email verification is enforced at data and callable boundaries, not only in UI.
- Firebase mode never falls back to demo repositories.
- Emulator and production configuration use the correct project and platform app IDs.
