# Module 8 implementation contract

Original C3/C4 remain authoritative. This records compatible additions to existing organization-scoped records; no duplicate Coach identity/profile collection or bulk migration is introduced.

| Record | Trusted facts and access |
|---|---|
| Firebase Auth | Existing Coach login, reset email, password reauthentication/change and logout. No passwords or tokens in Firestore. |
| `users/{uid}` | Optional `contactPhone` (normalized E.164 or empty), three `coachNotificationPreferences` booleans, `coachAccountRevision`, trusted `coachAccountUpdatedAtMillis`. Authenticated verified active canonical Coach commands only. Email remains Auth/provisioning owned. |
| `phoneClaims/{hash}` | Server-only uniqueness reservation; changing/clearing releases the previous claim without deleting history. No historical contact backfill. |
| `orgs/{org}/coachProfiles/{uid}` | Existing private professional draft, optional `consultationFeeMinor` (MYR integer minor units, null when absent) and immutable owned `photoPath` reference. Bio max 1,000 characters. Publication copies a reviewed draft. |
| `.../coachProfiles/{uid}/certifications/{id}` | Random 32-hex ID, title, issuer, owned Storage path, pinned upload generation/type/size, pending/approved/rejected/archived status, revision, trusted creation/update milliseconds, actor and rejection reason. Coach submits/archives; Admin approves/rejects with optimistic revision and idempotent receipt. |
| `.../certifications/{id}/history/{revision}` | Immutable version snapshots. Owner/Admin private reads; UI loads the latest 20 history entries on selection. Up to 100 revisions per document. |
| `.../coachProfiles/{uid}/certificationState/current` | Server-owned approved count, verification flag and bounded ID registry (100 total retained certifications). List pages contain 20 documents. |
| `orgs/{org}/coaches/{uid}` | Existing public projection, with optional fee/photo plus trusted `certificationVerified` and `approvedCertificationCount`. Publishing requires an active verified Coach identity and approved certification when BR-5 is enabled. Last approval removal atomically inactivates an existing listing. Approval does not automatically publish. |
| `orgs/{org}/coachPolicyHistory/{id}` | Server-only maintenance audit of the owner-approved transition of the sole unverified published listing to inactive. No fabricated Admin reviewer identity. |

Private Storage paths are `orgs/{org}/coachCertifications/{uid}/{32hex}` (PDF/JPEG/PNG) and `orgs/{org}/coachProfilePhotos/{uid}/{32hex}` (JPEG/PNG/WebP), maximum 5 MB, immutable create-only. Owner Coach and scoped Admin can read; list/update/delete are denied. Clearing/replacing a photo or archiving evidence retains the original object. File signatures are validated; PDF submission also requires an EOF marker.

Member photos are served through the App Check protected `getCoachPublishedPhotoCommand`, which verifies canonical organization, active membership and verified publication, bounds the generation-pinned download and rechecks authority/publication before returning bytes. Members cannot directly read Coach Storage objects. No token-bearing download URLs are stored or generated by this feature.

All new commands enforce App Check, active role/canonical organization checks and verified email. Server mutations use revision checks, trusted clocks and request receipts. Existing Coach publication commands are selectively updated; frozen Booking functions, Scheduler, AI and workout data are unchanged.

The approved deployment flag is `COACH_CERTIFICATION_ELIGIBILITY_ENABLED=true`. Existing listing inactivation changes only public status/revision/update metadata and creates a maintenance audit; identity/private profile and bookings remain intact. Local Admin UAT App Check debug credentials are owner-approved, private, excluded from Git and unsuitable as production deployment inputs.
