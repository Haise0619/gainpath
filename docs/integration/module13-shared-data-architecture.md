## Smallest safe next architecture

Retain the required project, `(default)` database, logical organization and **ordinary applications**, but introduce **one cross-module server-owned dataset scope** before enabling any fictional identities:

1. Place the entire fictional entity graph under one cohort namespace inside the default database, for example `orgs/gainpath/cohorts/fyp-v1/...`. This is a proposal, not an implemented or approved path layout. It is shared by all participating modules, not a Module 13-specific duplicate. Canonical exercise references may be reused read-only only after explicit validation.
2. A fresh Auth/App Check session resolver returns a server-verified dataset assignment. Ordinary app repositories obtain paths/callable routing from that immutable scope, never from a client demo flag. Existing UI widgets and navigation remain unchanged.
3. Keep cohort actors out of canonical `orgs/gainpath/members`. Untouched legacy payment/reward/Admin callables then fail closed rather than acquiring Demo Admin authority. Add server-owned assignment checks to provisioning before enabling Auth accounts, so older clients cannot auto-enroll those actors. Do not ship the old regex.
4. Reuse pure booking/report/recommendation services with scoped stores **and query adapters**; preserve their logical organization/exercise validation. Review each reader and writer, including generated notifications, worker triggers and Storage credential access. Do not inject slashes into `organizationId` or merely prefix some paths.
5. Add a distinct, reviewed synthetic-observation reader/projection for the verified fictional scope, with explicit fictional provenance, shared aggregation calculations and controlled Member progress hydration. Leave real capture acceptance unchanged. Require complete profile/catalog/Program source contracts and source-to-outcome emulator tests before apply.

This requires a scoped platform integration task, including legacy denial/old-client registration tests. It is the smallest proposed same-project solution that avoids retrofitting financial policy and org-wide permissions for a canonical Demo Admin. It still needs design/implementation and verification; namespacing alone is not proof. A flat `cohortId` alternative would additionally require compatible query changes, legacy-field handling/backfill, Rules and every Admin SDK authorization/aggregation boundary across critical services. Neither is silently activated here.
