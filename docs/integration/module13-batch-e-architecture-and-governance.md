### Concrete findings and correction ownership

1. **Synthetic transport isolation gap:** C/D trusted `localFixture` / `localDelivery` values alone do not bind a generic injected `DocumentStore` or eligibility dependency to a demo Firestore instance. A caller could accidentally pair those constants with a production store. A2 and the C queue *reader* already inspect actual SDK binding, but this does not protect every transaction/source. Root corrected the release boundary: the deployable facade permanently refuses execution, including with valid emulator capability and arbitrary injected handler. A WeakMap-minted capability validates actual SDK project/host/port/TLS/request metadata only; it is never a production execution grant. E test-only fixed composition constructs all stores/readers from that same verified demo SDK and validates before and after dispatch. The old flags alone do not provide physical isolation.
2. **Content coverage inconsistency, reproduced:** `exercise-insights-presentation.ts::contentCoverage` counted `status:published` records with `archived:true` or `isActive:false`, whereas B eligibility correctly rejects them. Its explicit `dayNumber` requirement also rejected legacy tutorial rows for which B/current destination legitimately defaults to day 1. New `functions/test/recommendation-release-boundaries.test.ts` reproduced 3 failures/3 passes before correction. Root corrected publication lifecycle filtering and the legacy day-one default. Independent rerun: 12/12 release-boundary and presentation tests passed. Invalid explicit day 0 remains a rejection.
3. **Queue-list privacy correction:** stored lead labels/needs/evidence/facets originally remained listable after Member purpose revocation. Root added current unique Member Auth and current insight/generation (+ external-AI purpose when applicable) checks before any same-kind facets/counts/output. A revoked/disabled participant refuses the whole response safely; terminal audits stay stored. Detail getter clock is refreshed after asynchronous identity work so expiry during that work cannot release stale details. Root recorded focused regression passes; final E verification consolidates them.
4. **Known release blockers, not silently corrected:** no trusted capture attestation; absent licence expiry schema; no comprehensive disclosure query/export protection; no approved retention; no production wrappers/adapters; no current deployed-baseline evidence. Source default-off and omission of production registration keep these blockers visible.

## 2. Capture-time and history authorization proposal — unapproved

Current backup heads contain `schemaVersion`, `kind`, `id`, `key`, `digest`, `payloadJson`, `classification:'provisional_member_backup'`, `updatedAtMillis`; revision copies repeat that shape. Session `startedAt`/`endedAt`/pose consent timestamps are inside Member-supplied payload. The backup validator checks syntax/consistency/identity, not a trusted physical capture clock. `updatedAtMillis` records server upload/processing time: an old session uploaded after grant is still old. Neither field may silently become “captured after consent.” Reading all payloads and discarding pre-grant ones already exceeds a pre-read history boundary.

Proposed new schema must distinguish **client-reported observation time**, **server received time**, and **trusted capture authorization interval**. Candidate metadata fields: schema/attestation version, organization/member/session/kind, payload digest, capture-authorization ID/version, attestation status (`verified_capture_interval`, `legacy_unattested`, `rejected`), trusted interval lower/upper bounds, server received time, source/client/analyzer versions and immutable provenance reference. Values are server-written after independently verifying a reviewed capture protocol; copying client timestamps into server fields does not make them trusted. Do not claim that App Check proves physical exercise, clock accuracy or clinical score validity.

An approved design could issue a short-lived server capture authorization bound to current verified account, organization, purpose revisions, session nonce and capture interval; verify final payload digest and completion under a replay-resistant protocol. Offline sessions and clock uncertainty need explicit semantics. If physical capture time cannot be established, the policy must keep those sessions excluded from a `from_grant` processing scope or seek a separately worded retained-history grant. A trusted authorization interval establishes authorization provenance, not medically validated exercise quality. The contract and expiry limits require review; none are activated here.

Proposed history read sequence:

1. Verify current Auth/App Check, active canonical Member/org and each required purpose; intersect their independently approved lower boundaries with requested window. Choose and document whether capture **start** must be at/after that intersection and capture **end** within the window; do not silently infer from session end alone.
2. Query only that Member's minimal server-owned metadata collection, filtering verified attestation/schema/source and the trusted capture interval before loading any history payload. Use bounded ascending `(trustedCaptureStartAtMillis, documentId)` cursor; enforce compatible end/interval constraints without fetching disallowed payload. A production policy must define overlap/straddling session treatment.
3. Only eligible metadata may authorize a point read of the digest-bound payload/revision. Match scope/session/digest/provenance, then run existing backup validator and exact compatibility extractor. Missing metadata, wrong digest, unsupported source/attestation or changed purpose fails closed. Never use a collection-group scan of all Member payloads.
4. Recheck canonical authority, purpose revision/history boundaries and metadata/digest before commit/response; abort on drift. Bound documents/bytes/time/provider operations. Separate metadata-query and payload-read counts in non-sensitive telemetry.

Proposed index is determined by the adopted metadata query, for example equality fields `(attestationStatus, attestationVersion, kind)` plus `trustedCaptureStartAtMillis ASC`, with the SDK document ID cursor; if explicit interval-end inequalities are selected, prove the precise multi-range query/index in staging. Do not deploy this illustrative schema/index. Current A2 document-ID-only backup query needs no composite but cannot provide the boundary. Current `consentScopedBackups(scope, window, after, limit)` supports an opaque cursor; the new adapter must bind that cursor to owner/window/policy/attestation version.

Migration proposal: inventory only metadata schemas under separately authorized scope; dry-run deterministic counts/rejection reasons without Member histories; write new metadata only from trustworthy historical attestations already present. Label legacy backups `legacy_unattested`; never promote them by reading client dates or upload timestamps. If no trustworthy historic attestation exists, there is no honest automatic from-grant backfill. Reviewed retained-history wording/approval is a separate route, not a rewrite of captured time. Use resumable actor-bound dry-run/migration IDs, immutable digest references, versioned verification/rollback and fresh grants; never grant or silently migrate real consent. No migration is implemented or run in E.

## 4. Authoritative data readiness and curation checklist

Trainer B service accepts only a bounded authoritative directory and canonically rereads each selected Coach. Production adapters and real curated mappings are absent. Verify all of the following before approval:

- Active organization/canonical Coach membership; current enabled verified Auth identity; published profile revision/source revision; permitted active branches and current roster assignment.
- Current certification-state IDs/count and actual approved certification records; issuer/title/source evidence reviewed by a responsible owner. Existing schema has no expiry/licence registry fields: record this limitation and choose a reviewed schema/procedure if those guarantees are required. Do not fabricate credentials or equate profile experience with certified expertise/quality.
- Server-owned exact exercise or reviewed expertise-to-exercise mapping, objective and level, reviewer/version/date/review trigger; teaching description checked for unsupported claims/injection. Free tags, bio text, category similarity and Gemini output are never eligibility authority.
- Current timezone, booking policy/version/window, 30/60-minute duration, member daily reservations/cap, Coach capacity, current exceptions/roster/day slots, conflicting Coach/Member bookings and valid shared branch.
- Consultation fee presence/range/currency and actual current checkout/quote constraints reviewed using the existing booking/payment flow. Eligibility does not certify affordability or reserve price/capacity; recommendation navigation cannot create hold/payment. Re-resolve on Send/delivery/detail/open and separately on booking choice.
- Privacy-minimized public teaching evidence and approved photo path only; no Member history/contact notes, bookings or private credential documents sent to Gemini or Member projection.

Content curation requires:

- Exact active/unarchived catalog ID (and active compatible target where applicable), current schema/source version and category/name; no fallback to invented catalog exercises.
- Actual `published`, `kind:routine`, active/unarchived Routine, valid blueprint/title/estimated minutes/exercises and current digest. Routine estimated duration is not exercise duration.
- Exact nested exercise index/ID/day; valid sets/reps/rest; tutorial steps and/or sanitized supported instructional video. Description/cover image alone is not instruction. Legacy absent day defaults to1 consistently; invalid explicit days fail.
- A reviewed `CuratedContentSuitability` row for each publication/index/digest with supported objective(s)/level(s), reviewer/revision, educational rationale and re-review on changed publication digest. Shared muscle category does not establish compatibility.
- Directed `CuratedCompatibleExercise` mapping with reviewed source/target exercise identity and scope, separate from suitability. Do not infer a reverse mapping automatically.
- Media playback/reachability, region/device/access rights, captions/transcript/alternative steps, low-bandwidth/failure behavior and safe supported URLs. Current validators establish syntax and authored instruction, not network accessibility/licensing.
- Current authorized Member `published_routine_exercise_tutorial` destination and existing player. Re-resolve current publication/index/exercise/day when opening; withdrawal, stale digest, invalid media/source and missing curation must abstain/refuse safely.

`no_candidate` / `no_eligible_published_instruction` and no qualified Coach are valid outcomes. Never loosen credential, branch, source or pedagogical eligibility to fill queues. No production inventory was inspected; “readiness unknown” is the correct real-data status.
